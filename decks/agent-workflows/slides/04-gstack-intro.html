gstack · 角色切换的 CEO 工作流

核心理念

gstack 由 Y Combinator CEO Garry Tan 开发，核心思想是「认知模式切换」——让 Claude 在不同阶段扮演不同角色，从 CEO 的战略视角到 QA 的细节检查，每个角色有明确的职责边界。

核心差异：不是自动化流程，而是让 Claude 像「换帽子」一样切换思维模式，每个模式有独立的 prompt 和检查清单。

典型工作流
/plan-ceo-review
新功能想法 → CEO 视角审视产品价值，找 10-star 方向
/plan-eng-review
方向锁定 → Eng Manager 设计架构、数据流、边界情况
/review
代码完成 → Paranoid Engineer 找 CI 抓不到的 bug
/browse
部署后 → QA 登录、点击、截图，60 秒完整 QA
/ship
验证通过 → Release Engineer sync main、跑测试、开 PR
适合场景
  • ✓ 创业团队，需要 CEO 视角的产品决策
  • ✓ Web 应用，需要浏览器自动化测试
  • ✓ 单人开发者，想要「虚拟团队」的角色分工
  • ✓ 需要显式控制每个阶段，而非自动化流程
