Best Practices & FAQ

最佳实践与常见问题

通用最佳实践
  • 从简单开始
    先用 Claude Code 原生能力，遇到瓶颈再引入插件
  • 理解插件哲学
    每个插件有独特理念，选择与你工作方式匹配的
  • 渐进式采用
    不要一次性启用所有 skills，按需添加
  • 保持 CLAUDE.md 简洁
    只保留真正有用的指令，避免信息过载
  • 定期清理
    移除不再使用的 skills 和 agents，保持环境清爽
插件特定建议
  • Superpowers
    接受强制 TDD，这是质量保证的核心价值
  • gstack
    不要跳过 /plan-ceo-review，产品视角很重要
  • oh-my-claudecode
    Team 模式适合大任务，小任务用 Autopilot
  • everything-claude-code
    选择性安装，避免 156 skills 全部加载
常见问题
可以同时使用多个插件吗？
可以，但要注意冲突。建议选择一个主插件，其他作为补充。例如：Superpowers 做主流程 + gstack 的 /browse 做 QA。
哪个插件学习曲线最低？
gstack 最低——8 个角色概念直观，每个 skill 独立使用。oh-my-claudecode 次之，官方口号是「Don't learn Claude Code. Just use OMC」。
哪个插件适合团队协作？
oh-my-claudecode 的 Team 模式专为团队设计，多 agent 并行 + 共享任务列表。everything-claude-code 适合企业，全栈能力 + 持续学习。
插件会影响 Claude Code 性能吗？
会。大量 skills/agents 会增加 prompt 长度。建议选择性安装，定期清理不用的。ECC 的选择性安装模式就是为了解决这个问题。
进阶建议
组合使用策略：
1. Superpowers 做主流程（强制 TDD + 代码审查）
2. gstack 的 /browse 做浏览器自动化测试
3. oh-my-claudecode 的特定 agent 做专业任务（如 security-reviewer）
4. everything-claude-code 的 domain skills 做技术栈支持
