Chapter 12 · Best Practices

最佳实践

构建高质量 Plugin 和 Marketplace 的关键原则

✓  推荐做法
1

单一职责原则

每个 Plugin 专注一个领域（代码质量 / Git 工作流 / 测试），避免大而全的「瑞士军刀」

2

Skill description 写精准

description 字段决定 Claude 何时自动加载 Skill，写得越精准，触发越准确，误触发越少

3

blocking Hook 谨慎使用

blocking Hook 会阻止工具执行，只在真正需要拦截时使用，避免影响正常工作流

4

语义化版本号

遵循 semver：patch 修 bug，minor 加功能，major 破坏性变更。Marketplace 依赖版本号追踪更新

✕  常见错误
!

把文件放进 .claude-plugin/

只有 plugin.json 放在 .claude-plugin/。Skills、Hooks 等放在 Plugin 根目录

!

Agent 中配置 hooks / permissionMode

Plugin 提供的 Agent 不支持 hooks、mcpServers、permissionMode frontmatter，这是安全限制

!

name 字段用非 kebab-case

Plugin name 必须是 kebab-case（如 code-quality），它会成为所有命令的命名空间前缀

!

在 Skill 中硬编码路径

使用 ${CLAUDE_PLUGIN_ROOT} 变量引用 Plugin 内的文件，避免绝对路径导致跨机器失效
